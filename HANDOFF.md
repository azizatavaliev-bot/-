# HANDOFF: платформа AdOps для Claude Code (десктоп)

Это полный контекст проекта. Прочитай целиком, затем выполни раздел «Первая задача».

## 1. Кто и зачем
Азиз, предприниматель из Бишкека (Кыргызстан/СНГ). Ведёт агентство, где таргетологи работают с рекламными аккаунтами клиентов в Facebook/Instagram Ads. Есть внутренняя система **Prime**: в ней вносят отчёты, финансы, отчёты сотрудников, оплату клиентов, доли владельца и исполнителей (в процентах), у одного человека несколько проектов. Схему данных Prime Азиз не знает, стек неизвестен.

**Идея.** Вместо ручного заполнения отчётов сотрудник подключает свои Facebook-аккаунты клиентов по API-токену, а система:
- каждый день сама заполняет отчёты (расход, результаты, цена результата);
- сравнивает результативность и расходы, находит проблемы;
- включает ИИ-советника, который видит все цифры и подсказывает настройки таргета;
- даёт управлять рекламой через общий Telegram-бот (в Prime уже есть бот с ролями: владелец, лид, сотрудник, таргетолог, маркетолог);
- держит инструкцию по токенам внутри платформы (бессрочный токен, 60-дневный, обмен, ошибки);
- считает зарплаты: сколько клиент платит, сколько владелец, сколько исполнитель, по проектам.

**План (решение Азиза):** сначала отдельная платформа, ручной тест на первом аккаунте, потом встраивание в Prime.

Что человек делает сам, API не умеет: привязка и оплата карты, проверка личности, разблокировка аккаунта.

## 3. Что реализовано (platform/)
- **Роли**: владелец и сотрудник. Сотрудник видит только свои проекты; финансовые поля проекта (оплата клиента, проценты, исполнитель, статус) меняет только владелец.
- **Проекты**: `ad_account_id`, зашифрованный токен, `name_filter` (фильтр кампаний по части названия — несколько направлений в одном аккаунте), `result_type` (auto/lead/messages/purchase/link_click), `client_fee`, `employee_pct`, `owner_pct`, архив с датой окончания.
- **Токены**: проверка (`/{act}` + `debug_token` при заданных `META_APP_ID/SECRET`), статус ok/expiring/invalid/none, обмен короткого токена на 60-дневный.
- **Синхронизация**: каждые 30 минут вчера+сегодня, по кампаниям с агрегацией по дню; результаты без дублей (внутри группы берётся максимум: `lead` и `onsite_conversion.lead_grouped`). Даты по часовому поясу рекламного аккаунта. Ручные правки не перетираются: хранится `auto_spend/auto_results`, расхождение даёт флаг.
- **Анализ** (`analyze` в sync.js): нет расхода, падение/рост расхода >50%, цена результата +30% к средней за неделю, расход без результатов, токен умирает, ручная правка ≠ Facebook, нет данных за вчера.
- **Зарплаты**: проценты от оплаты клиента; проект учитывается, если был активен хоть часть месяца (без пропорции по дням).
- **Telegram**: общий бот, привязка одноразовым кодом из «Профиля» (15 мин, защита от перебора). Команды `/today /yesterday /projects /salary /reset /help`, обычный текст идёт в ИИ. Утренняя сводка (час настраивается).
- **ИИ-советник** (веб-вкладка и Telegram, одно ядро): инструменты `list_projects, get_reports, live_insights, list_entities, analyze_project, sync_now, edit_report, my_salary, team_overview (только владелец), ads_set_status, ads_set_budget, confirm_action, cancel_action`.
- **Безопасность изменений рекламы**: статус/бюджет меняются двухшагово. Инструмент только создаёт запрос; `confirm_action` падает, если вызван в том же ходе (`run_id`), чужим пользователем или через 30 минут. Лимит изменения бюджета за раз (по умолчанию 30%) проверяется при предложении и при выполнении.
- **Инструкция внутри UI** (вкладка «Инструкция»): бессрочный токен системного пользователя пошагово, токен на 60 дней, форма обмена, что делает платформа сама и что только человек, безопасность токена, таблица ошибок (190, 200/273, 17/613/4), привязка Telegram.
- UI: Дашборд, Проекты, Отчёты (правка, CSV), Зарплаты, Советник, Инструкция, Профиль, Команда, Настройки, Журнал.

Проверено: 9 тестов проходят (`cd platform && npm test`): шифрование, синхронизация, ручные правки, анализ, токен 190, изоляция сотрудников, подтверждения, зарплаты, Telegram (подставной сервер), API и роли. UI прогнан Playwright без JS-ошибок. Цикл агента проверен на подставном API Claude.

**НЕ проверено на живых системах**: реальный Facebook-аккаунт, реальный Telegram-бот, реальный ответ Claude. Это и есть цель ручного теста.

## 4. Первая задача (запусти и проверь)
Требуется Node.js 22.13+ (`node -v`).
```bash
git clone https://github.com/azizatavaliev-bot/-.git
cd -   # или как назвалась папка
git checkout claude/great-heisenberg-k18gn7
cd platform
npm install
npm test            # ожидаем 9 из 9
npm run setup       # создаёт .env, печатает логин owner и пароль
npm start           # http://localhost:3000
```
Проверь, что сайт открывается, и покажи Азизу логин/пароль из вывода `npm run setup`. Если порт 3000 занят: `PORT=3001 npm start`. Если ошибка про `node:sqlite` — Node старше 22.13.

Ручной тест первого аккаунта (ведёт Азиз):
1. Войти как `owner`.
2. Проекты → «Новый проект» → название и ID рекламного аккаунта (цифры или `act_…`) → Сохранить.
3. В карточке вставить токен → «Сохранить токен и проверить». Ожидаем: название аккаунта, валюта, загрузка 14 дней.
4. Дашборд и Отчёты: сверить расход с Ads Manager за те же дни.
5. Если в аккаунте несколько направлений, задать «Фильтр кампаний» и «Что считать результатом».
6. Для советника и Telegram добавить в `.env` `ANTHROPIC_API_KEY` и `TELEGRAM_BOT_TOKEN`, перезапустить; в «Профиле» нажать «Подключить Telegram».

Если проверка токена падает, вероятные причины: токен не на тот аккаунт (нет доступа у системного пользователя, код 200/273), токен истёк (190), в приложении нет `ads_read/ads_management`, версия Graph API устарела (`META_API_VERSION`, по умолчанию `v23.0` — проверь актуальную). Диагностика: смотри лог в терминале и вкладку «Журнал».

## 6. Риски и важные решения
- `APP_SECRET` шифрует токены. Потеряешь — токены придётся вводить заново. Хранить отдельно от сервера.
- SQLite хватит на десятки сотрудников; для сотен — Postgres.
- Токен системного пользователя (срок «Никогда») — единственный по-настоящему бессрочный путь. Для чужих аккаунтов клиент должен дать доступ партнёру в Business Manager. App Review для своих аккаунтов не нужен.
- Правила для ИИ в платформе: цифры только из инструментов, не делать выводов на 2–3 конверсиях, изменения только после «да».
- Не коммитить `.env` и `data/` (уже в `.gitignore`).

## 7. Стиль общения с Азизом (важно)
Общайся на «ты», по-деловому и по-человечески. Сначала вывод, потом почему, потом следующий шаг. Ответ до ~120 слов, абзац не больше 2 предложений, пустая строка между абзацами, эмодзи-якоря (🎯 вывод · ⚡ механика · ⚠️ риск · ✅ шаг · ❓ вопрос), жирным только цифры, термины и действия. Честность важнее вежливости: сырую идею называй сырой и объясняй почему. Варианты: максимум 3, с рекомендацией «на твоём месте я бы…». Азиз пишет голосом, в сообщениях бывают ошибки распознавания: лови смысл, при непонятках один уточняющий вопрос. Он предприниматель и не программист: объясняй, что нажать и что ожидать на экране. Лучше делай, чем спрашивай, но перед необратимым (деплой на сервер, трата денег, публикация) подтверждай.
