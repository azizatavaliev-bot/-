# Лендинг с анкетой и таймером на 24 часа

Одностраничный сайт: человек заходит по ссылке — с этого момента у него ровно
24 часа, чтобы заполнить анкету. Таймер идёт непрерывно, даже когда сайт закрыт,
и привязан к устройству, с которого был первый заход.

## Как устроен таймер

1. **Первый заход.** Сервер выдаёт браузеру cookie `sid` и записывает в файл
   `deadline = сейчас + 24 часа`.
2. **Повторный заход.** Браузер присылает тот же `sid` — сервер возвращает
   **тот же самый** `deadline`. Время не перезапускается и не продлевается.
3. **Сайт закрыт.** Дедлайн — это метка времени в базе, а не счётчик в браузере.
   Пока человека нет, время всё равно уходит.
4. **Отправка анкеты.** `POST /api/submit` сверяет дедлайн **на сервере**.
   Подкрутить таймер в консоли браузера бесполезно — заявка не пройдёт.

Браузер синхронизируется с сервером при загрузке, при каждом возврате на вкладку
и раз в минуту, поэтому переведённые часы на телефоне таймер не ломают.

## Запуск

```bash
cd landing
cp .env.example .env      # задайте ADMIN_KEY
npm start                 # http://localhost:3000
```

Зависимостей нет — только Node.js 18+. `npm install` не требуется.

## Настройка под свой оффер

Всё в одном файле — `config.js`:

| Параметр | Что задаёт |
|---|---|
| `windowHours` | сколько часов даётся на анкету (по умолчанию 24) |
| `brand` | заголовки, подзаголовок, буллеты, тексты экранов «успех» и «время вышло» |
| `fields` | поля анкеты: `text`, `tel`, `email`, `number`, `textarea`, `select` |
| `cookieDays` | сколько браузер помнит выданный ID (должно быть заметно больше `windowHours`) |

Поля проверяются и на клиенте, и на сервере — достаточно добавить поле в
`fields`, форма и валидация подстроятся сами.

## Заявки

- Таблица: `/admin.html?key=ВАШ_КЛЮЧ`
- Выгрузка в Excel: `/api/leads.csv?key=ВАШ_КЛЮЧ`

Данные лежат в `data/` в формате NDJSON (одна строка = одна запись). Файлы
только дописываются, поэтому аварийная остановка процесса не портит базу.
В git они не попадают — при переносе на другой сервер скопируйте каталог `data/`.

## Деплой

Подойдёт любой хостинг, где можно запустить Node-процесс (VPS, Railway, Render).
Порт берётся из `PORT`.

- Поставьте сайт **за HTTPS** (nginx + certbot или прокси хостинга) — тогда
  cookie автоматически получит флаг `Secure`.
- Каталог `data/` должен лежать на постоянном диске, а не в эфемерной файловой
  системе, иначе при передеплое заявки и таймеры обнулятся.

## Ограничения, о которых стоит знать

- Привязка идёт к браузеру, а не к человеку. Режим инкогнито, другой браузер или
  другое устройство дают новые 24 часа. Это цена того, что вход не требует
  регистрации.
- Если нужна защита без обхода — анкету открывают после ввода телефона или
  почты, и дедлайн вешается на контакт, а не на cookie. Механика сервера
  та же, меняется только ключ сессии.
- Очистка cookie в браузере тоже сбрасывает таймер: для человека это выглядит
  как новый первый заход.
