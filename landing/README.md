# NEW G — лендинг курса с анкетой и таймером на 24 часа

Одностраничный сайт: человек заходит по ссылке — с этого момента у него ровно
24 часа, чтобы заполнить анкету на бесплатную консультацию. Таймер идёт
непрерывно, даже когда сайт закрыт, и привязан к устройству первого захода.

## Как устроен таймер

1. **Первый заход.** Сервер кладёт в cookie дедлайн `сейчас + 24 часа`,
   подписанный секретным ключом (HMAC-SHA256).
2. **Повторный заход.** Браузер присылает ту же cookie — сервер возвращает
   **тот же** дедлайн. Время не перезапускается и не продлевается.
3. **Сайт закрыт.** Дедлайн — это метка времени, а не счётчик в браузере.
   Пока человека нет, время всё равно уходит.
4. **Отправка анкеты.** `POST /api/submit` проверяет дедлайн по подписи.
   Подкрутить таймер в консоли браузера бесполезно: без ключа подпись
   не сойдётся, и сервер выдаст новый честный срок вместо подделанного.

Хранилище для таймера не нужно вообще — поэтому сайт одинаково работает
и на обычном сервере, и на serverless-хостинге.

Браузер синхронизируется с сервером при загрузке, при каждом возврате на
вкладку и раз в минуту, поэтому переведённые часы на телефоне таймер не ломают.

## Запуск

```bash
cd landing
cp .env.example .env      # задайте SESSION_SECRET и ADMIN_KEY
npm start                 # http://localhost:3000
```

Зависимостей нет — только Node.js 18+. `npm install` не требуется.

## Настройка под оффер

| Файл | Что менять |
|---|---|
| `config.js` | длина окна (`windowHours`), поля анкеты, тексты экранов «успех» и «время вышло» |
| `public/index.html` | весь текст лендинга: заголовки, программа, суммы в кейсах |
| `public/cases/` | фото учеников для блока результатов (`1.jpg` … `6.jpg`) |
| `public/styles.css` | цвета в блоке `:root` |

Поля анкеты проверяются и на клиенте, и на сервере: достаточно добавить поле
в `config.fields`, форма и валидация подстроятся сами.

## Куда приходят заявки

Два независимых приёмника, работают одновременно:

- **Файл** `data/leads.ndjson` — на сервере с постоянным диском.
  Просмотр: `/admin.html?key=ВАШ_КЛЮЧ`, выгрузка: `/api/leads?format=csv&key=...`
- **Telegram** — если заданы `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`,
  анкета сразу падает в чат. На serverless-хостинге это основной способ,
  потому что там файловая система только для чтения.

Заявка также всегда пишется в лог процесса — последняя линия обороны,
если оба приёмника отвалились.

## Переменные окружения

| Переменная | Зачем |
|---|---|
| `SESSION_SECRET` | ключ подписи дедлайна. Задать один раз и не менять — смена обнуляет таймеры у всех |
| `ADMIN_KEY` | доступ к списку заявок |
| `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID` | доставка заявок в Telegram |
| `PORT` | порт (по умолчанию 3000) |

## Деплой

- **Обычный сервер / VPS.** `npm start` за nginx с https. Каталог `data/`
  должен лежать на постоянном диске.
- **Vercel.** `vercel.json` и точки входа в `api/` уже готовы: статика
  раздаётся из `public/`, API работает как функции. Переменные задаются
  в Settings → Environment Variables и применяются со следующего деплоя.
  Файловая система там только для чтения, поэтому `data/leads.ndjson`
  и страница `/admin.html` не работают — заявки нужно слать в Telegram.

Под https cookie автоматически получает флаг `Secure`.

## Ограничения

- Привязка идёт к браузеру, а не к человеку: инкогнито, другой браузер или
  другое устройство дают новые 24 часа. Это цена входа без регистрации.
- Очистка cookie тоже сбрасывает таймер — для человека это новый первый заход.
- Нужна защита без обхода — анкету открывают после ввода телефона, и дедлайн
  вешается на контакт. Серверная механика та же, меняется только ключ сессии.
